# Онлайн-автозагрузка Авито

Сервис хранит объявления, отдаёт Авито XML-фид по постоянному HTTPS-адресу и читает отчёты автозагрузки через Avito API.

## Что нужно для запуска

1. Развернуть папку на хостинге с постоянным диском (Render, Railway, VPS или аналог).
2. Создать защищённые переменные по `.env.example`. `AVITO_CLIENT_SECRET` нельзя добавлять в репозиторий. `AVITO_USER_ID` можно оставить пустым: сервис определит его через `/core/v1/accounts/self`.
3. Подключить в кабинете Авито адрес вида `https://домен/feed/FEED_TOKEN.xml`.
4. Настроить расписание обработки в разделе «Автозагрузка».

Для Render в проекте есть `render.yaml`: создайте Blueprint из репозитория, задайте `AVITO_CLIENT_ID` и `AVITO_CLIENT_SECRET` как Secret, затем скопируйте сгенерированные `FEED_TOKEN` и `ADMIN_TOKEN` из настроек сервиса.

`client_id` и `client_secret` используются для чтения отчётов и статусов. Публикация и обновление объявлений происходят, когда Авито забирает XML по расписанию.

## Добавление объявления

```bash
curl -X POST https://домен/api/ads \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  --data @ad.json
```

Повторный запрос с тем же `id` обновляет объявление. `id` и `fields.Id` должны совпадать и оставаться постоянными. Удаление записи из фида может привести к снятию объявления Авито при следующем цикле, поэтому используйте удаление осознанно.

## Проверка

- `GET /health` — состояние сервиса.
- `GET /feed/FEED_TOKEN.xml` — XML-фид.
- `GET /api/ads` — список объявлений, нужен `ADMIN_TOKEN`.
- `GET /api/avito/reports/last` — последний отчёт Авито, нужен `ADMIN_TOKEN`.
- `GET /api/avito/account` — данные подключённого аккаунта, нужен `ADMIN_TOKEN`.
- `GET /api/avito/items/ID` — статус объявления, нужен `ADMIN_TOKEN`.

Локальная проверка: `npm run check`.
